# issue-44 execution-observation scout brief

Mode: **parallel sweep**, 4 angles dispatched concurrently as subagents in
one turn, aimed at survey §5's gaps A-D (red-run evidence standards;
single-finding audit shape; self-reported results without CI;
traceability-audit handling of deliberate exclusions). **1 stage total**,
~50s wall-clock — all four converged on the same "evidence must be traced
or the claim is recorded as unverified" position, so a deepening round
would not move any decision in the proposal.

## Must-bes for a delivery-observation record of this kind

- Every conclusion traces to a specific piece of evidence via a stable
  cross-reference; audit standards treat an untraced conclusion as
  incomplete even when it happens to be correct
  (<https://eduyush.com/en-us/blogs/cima/audit-documentation>).
- A single finding is self-contained in five parts — criteria, condition,
  cause, consequence, corrective action — so it needs no surrounding
  report to be actionable
  (<https://www.dimovaudit.com/blog-posts/what-are-the-5-cs-of-audit-findings>).
- Timeline is facts-first: chronological events with timestamps, kept
  separate from causal narrative
  (<https://incident.io/blog/sre-incident-postmortem-best-practices>).
- A coverage claim is checked by sampling the chain requirement → test →
  execution record, not by trusting the claim
  (<https://beefed.ai/en/requirements-traceability-matrix-audit-proof>).

## Performance axes the field competes on

1. **Evidence durability** — a "would have failed" claim is normally
   backed either by an actual re-run against pre-fix code, or by
   mutation/fault-seeding as its standard substitute when no run artifact
   survives (<https://en.wikipedia.org/wiki/Mutation_testing>,
   <https://developers.openai.com/codex/security/plugin/fix-findings>).
2. **Independence of attestation** — CI required-status-checks exist
   because author-side reports are not independent; SLSA makes the same
   point structurally, that provenance generated by the party being
   attested is a weaker level
   (<https://docs.github.com/en/repositories/configuring-branches-and-merges-in-your-repository/managing-protected-branches/about-protected-branches>,
   <https://slsa.dev/spec/draft/build-provenance>).
3. **Disposition of deliberate gaps** — an exclusion counts as accepted
   only when written down as a formal item with stated reason and
   approval (IEEE 829 "Features Not to Be Tested"; ISO 9001 concession;
   DO-178C coverage disposition); undocumented, it is recorded as a gap
   (<https://www.coleyconsulting.co.uk/testplan.htm>,
   <https://www.theauditoronline.com/the-importance-of-introducing-a-formal-concession-process/>,
   <https://visuresolutions.com/do-178-guide/testing-coverage>).

## Adopt / skip

- **Adopt**: the 5-C finding shape folded into this role's mandated
  impact/timeline/root-cause/action-item four-part form; per-claim
  citation to commit SHA / `file:line` / comment URL; explicit
  classification of the mobile-overflow exclusion as documented-deviation
  vs. coverage-gap against where its rationale and approval actually sit.
- **Skip**: mutation testing / fault seeding as *this role's own*
  verification move — the field offers it as the substitute for a lost
  red run, but running it here would mean re-executing the observed
  role's task, which this role is prohibited from doing. It is adopted
  only as the *criterion* against which the observed record's own
  evidence is read, never as an action taken.
- **Skip**: re-running the pytest suite to check the 63/63 claim, for the
  same reason; the finding instead records what independent attestation
  does and does not exist on `main`.

## Segment fit

Same segment as an internal delivery audit of one merged change by a
non-author reviewer — not an incident postmortem (no outage) and not a
conformance review (that is issue #44's parallel step-2 role).

## Gap line

Already met by the current state: the observed record carries a
traceability section and an AC crosswalk
(`docs/issue-44/reports/test-authoring.md:137-156`, `:223-239`), and its
exclusion of mobile-overflow is written down with a stated reason
(`:251-259`) — the IEEE-829-shaped half of must-be 3. Missing: any
attestation independent of the author — `ls .github/workflows/` shows
only `deploy-board.yml`, no test gate — and any surviving artifact from
the pre-fix red runs, which the record itself states were "deleted after
use, never committed" (`:208`). These two absences are what the phase-2
evidence plan has to be built around rather than assume away.
